# Team cards in the native print queue

The BBTC userscript 0.2.0 only offers team import. Card selection, quantities, duplex settings, preview, printing, removal and print-state persistence are handled by the existing application UI.

Queue records can now carry an optional `backBlob` alongside `blob`. In the native renderer, this individual back takes precedence over the common back. Cards without an individual back use the common back when present, otherwise their back position is blank. Back pages are mirrored using the existing duplex function, including partially filled sheets. Quantities duplicate both sides together. This also recognizes front/back records previously generated by userscript 0.1.0.

`BloodBowlPrintQueue.importRecords(records)` commits complete imported pairs atomically and returns their IDs. Records include `bbtc.batch` and `bbtc.number`; reimporting those players replaces their previous profiles and annexes while preserving other cards and stored application state.

`loadPrintQueue({selectIds})` reloads the existing list, preserves its current selections and quantities, and selects newly imported IDs. The usual preview scheduler then renders the sheet and persists its state.

Validation: native functions exercised against the print-page DOM and an IndexedDB implementation; individual/common/missing backs, quantities, both duplex flips, partial sheets, native preview and printing, selection persistence, removal and atomic reimport. Userscript checks confirm one import entry point and a Bootstrap preparation dialog, without a second card list, preview, printer or database implementation.
